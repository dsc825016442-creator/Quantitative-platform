# 市场研究平台架构

## 目标

- 每天北京时间 18:30 自动生成可追溯的 Tushare 市场快照。
- 页面始终读取最近一次质量合格快照；辅助模块降级时仍发布并明确标注。
- 今日、20 日、60 日必须来自真实交易日序列，不再通过比例缩放模拟。
- 数据缺失、权限不足和质量异常必须显式显示并可被监控。

## 非功能要求

- 安全：Tushare Token 只保存在 Sites；GitHub 仅保存独立刷新密钥。
- 可靠性：任务失败最多重试三次；失败时保留上一批成功快照。
- 可追溯：记录每次任务的开始、结束、状态、交易日、模块结果与错误。
- 性能：页面只读取聚合快照；不在浏览器加载全市场原始明细。
- 成本：当前使用单站点、单 D1 数据库，不引入额外付费基础设施。

## 数据流

```text
GitHub 定时任务
      │ ① Bearer 刷新密钥
      ▼
受保护刷新接口 ──► Tushare Pro
      │                │
      │ 聚合/质量检查  │ 行情、估值、指数、资金、事件、基金期货
      ▼                ▼
Cloudflare D1：快照 + 研究输入 + 任务日志
      ▲
      │ ② 受保护输入 / ③ Python分析写回
Python研究引擎（GitHub Actions）
      │
      ▼
公开只读快照接口 ──► 研究驾驶舱
```

## ADR-001：采用聚合快照而非浏览器直连 Tushare

### 状态

Accepted

### 决策

由服务端读取密钥、拉取并聚合数据，将页面所需结果写入 D1。浏览器仅访问不含密钥的只读快照。

### 权衡

- 优点：密钥不泄露、页面响应稳定、失败可回退、查询成本可控。
- 缺点：当前不保存所有逐笔原始记录；深度回测需要后续扩展明细层。

## ADR-002：P0 历史窗口先使用核心指数序列

### 状态

Accepted

### 决策

首次回填沪深 300、上证 50、中证 500、中证 1000、创业板指的真实 60 日历史，用于页面窗口与市场状态；全市场逐股历史和行业历史在 P1 分批落库。

### 权衡

- 优点：一次刷新即可获得真实 20/60 日窗口，避免在边缘函数中一次下载数十万行。
- 缺点：P0 的历史窗口代表核心指数，不等同完整行业和个股截面。

## 主要故障与处理

| 故障 | 处理 |
|---|---|
| Tushare 单接口无权限 | 标记该模块不可用，其他模块继续 |
| 核心日线为空 | 整批失败，不覆盖旧快照 |
| 数据质量检查失败 | 快照标记 partial，页面展示告警 |
| 定时任务网络失败 | 最多重试三次并保留旧快照 |
| D1 写入失败 | 任务记录失败，公开接口继续返回旧数据 |

## ADR-003：P2 使用可解释规则与无未来函数模拟

### 状态

Accepted

### 决策

“AI 观察”当前由确定性规则生成，每条结论附接口证据，不调用外部大模型。组合仅输出研究权重；历史模拟使用前 20 日已知价格生成下一交易日权重，并与五指数等权基准比较。

### 权衡

- 优点：结果可复算、无需新增密钥或推理费用，并避免当日信号使用当日收益。
- 缺点：当前样本窗口较短，不含交易费用、滑点和申赎约束，不能视为实盘业绩。

## ADR-004：21 只研究成分采用可复算分层抽样

### 状态

Accepted

### 决策

每日按总市值排序：前 7 只作为大盘核心；市值排名 501–2000 中按成交额选择 7 只作为中盘活跃；其余股票按成交额选择 7 只作为小盘活跃。每只成分单独回填历史行情并计算 20/60 日收益、距 20 日均线和 60 日最大回撤。

### 权衡

- 优点：固定规则、数量稳定、可以每日复算，不再依赖手工示例名单。
- 缺点：这是研究代表篮子，不是指数公司发布的官方成分；换手率和交易成本需在实盘前另行约束。

## ADR-005：采用 Python 离线研究引擎与 TypeScript 在线服务

### 状态

Accepted

### 背景

在线刷新已包含近百次外部查询，因子、组合和回测继续增长会增加边缘函数复杂度。页面与公开 API 已稳定运行，不适合整体重写。

### 决策

- TypeScript 继续负责 Tushare 密钥、数据采集、D1、公开 API、页面和 Python 失败时的兜底分析。
- Python 3.12 负责观察、因子、研究组合和无未来函数回测。
- Python 只通过现有 `REFRESH_SECRET` 访问受保护研究输入并写回结果，不持有 Tushare Token。
- 协议固定为 `research-inputs/v1` 与 `research-analytics/v1`；写回时必须匹配交易日且组合权重合计为 100%。
- 公开快照删除内部 `researchInputs`，避免无意扩大数据分发面。

### 后果

- 正面：研究计算可独立测试和扩展；Python 失败时页面仍有 TypeScript 兜底；无需新增付费基础设施或复制 Tushare Token。
- 负面：每日任务多一个运行阶段；两种语言需要维护相同协议；GitHub Actions 故障会使引擎暂时停留在兜底模式。
- 替代方案：整体改成 Python 会破坏现有 Sites 部署；把 Tushare Token 放入 GitHub 可简化管道，但扩大密钥暴露范围，因此未采用。

### 运行与故障处理

| 故障 | 处理 |
|---|---|
| Python 输入协议不匹配 | 任务失败，保留 TypeScript 兜底结果 |
| Python 输出交易日过期 | 写回接口返回 409，不覆盖新快照 |
| Python 输出权重或结构无效 | 写回接口返回 400 |
| Python 任务超时 | GitHub 任务失败并由每日巡检提示 |
| Python 依赖变化 | 第一阶段仅使用 Python 标准库，固定 Python 3.12 |
